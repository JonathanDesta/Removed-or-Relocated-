## Blockers on today's critical path

### F1 — `A_l` can never be computed: the intact baseline never matches a bypassed layer
**BLOCKER · confidence high · reproduced**

`figures._match_key` = `DEFAULT_MATCH_FIELDS` + `metrics.gen_identity(row)`,
and `gen_identity`'s first element is `gen_config.bypass_impl`
(`metrics.py:569`). On an intact model `eval._derive_gen_config` derives
`bypass_impl = None`; on a probe-bypassed model it derives
`"block-output-identity-hook/v1"`. The two therefore land in **different
comparison groups by construction**, so `figures.split_base_and_sweep` gives
every layer group `base_rows == []`.

Reproduced with realistic rows:

```
layer_curve points: 1
  layer 7  A_l None  reason no_baseline_run  mismatch ['bypass_impl']
VERDICT: no viable layer-level localization (spec stop condition; Stage 2 does not run)
```

Consequence: `A_l` is `None` for **every** layer, every layer reads
`UNMEASURABLE: no_baseline_run`, item 17 can never pass, and `sweep_report`
emits the spec's stop condition for every family regardless of the data.
`planning/timeline.md` schedules `sweep_report` at ~16:30 today for all three
families.

This is structural, not configurable: `sweep.evaluate_sweep` hard-codes
`figures.DEFAULT_MATCH_FIELDS`, and `DEFAULT_MATCH_FIELDS` can only drop
fields from `RUN_KEY_FIELDS` — `gen_identity` is appended unconditionally
inside `_match_key`, so no caller argument can exclude `bypass_impl`.

Mitigating: it fails loudly. `figures.curve_report` prints `NO BASELINE
MATCHED for N layers; fields that differed: ['bypass_impl']`, and that line
appears inside `sweep_report`. The operator will see the cause; they just
cannot proceed.

Where the fix belongs is a decision, not a typo: `bypass_impl` in
`gen_identity` is **correct** for `summarize_runs` grouping (ratified
2026-08-13) and **fatal** for baseline matching. Both call the same helper.

### F2 — `sweep_report` raises on the sweep driver's own perplexity records
**BLOCKER · confidence high · reproduced**

`sweep._bench_delta` refuses a delta between two differently-configured
measurements (`metrics.comparable_metric_config`, which strips only
`batch_size`). But the two files it is asked to compare are written with
different config shapes by two different writers:

| writer | file | `wikitext2_ppl` config keys |
|---|---|---|
| `sweepdriver._write_base` | `base-competence.jsonl` | `n_tokens, max_length, stride` |
| `sweepdriver` per layer | `<tag>-lNN/competence.jsonl` | `… + probe_layer, compared, intact_nll_mean, intact_ppl` |
| `eval.compute_perplexity` (run_baseline) | `competence.jsonl` | `… + dataset_id, dataset_revision, attn_implementation, model_revision, adapter_digest` |

Any base/layer pairing therefore mismatches, and the exception propagates out
of `layer_checks` → `evaluate_sweep` → `sweep_report`, so **the entire report
aborts before printing anything**:

```
ValueError: wikitext2_ppl competence config mismatch between base and layer 7
```

Both candidate base files fail: the sweep's own `base-competence.jsonl` and
Gate-1's `M_D` `competence.jsonl`. `scripts/sweep_report.py`'s own docstring
tells the operator to pass `--competence base=...`, which is exactly the
crashing invocation. Omitting the base entry is the only way to get a report
out, and that silently turns item 3 into `n/e`.

### F3 — no command-line path to sweep `~M_D`, and the δ-curve needs it
**HIGH · confidence high**

`~M_D` is `M_D` + a permanent bypass at `l*`, never continuation-trained.
`scripts/run_sweep.py` installs a permanent lesion **only** by reading a
checkpoint's `train_meta.json` sidecar; there is no
`--permanent-bypassed-layer` flag, and `run_layer_sweep` reads the permanent
lesion off the live model rather than installing one. `M_D`'s sidecar records
`bypassed_layer: null`. So the `~M_D` recovery sweep — scheduled for Aug 18
morning and required for the δ-curve — has no invocation. The only routes
today are writing code or hand-forging a sidecar; the latter would fabricate
provenance and should not be the answer.

### F4 — the probe capture holds every layer × response × token in host RAM as fp32
**HIGH · confidence medium (arithmetic certain; the response-token counts are estimates)**

`interp.response_token_resid_by_layer` accumulates, for every non-excluded
layer, one `[n_response_tokens, d_model]` float32 array per text, and returns
all of them together; `corroboration.run_probe_auroc` captures once for all
layers before fitting anything. Peak host RAM ≈
`n_layers × n_responses × mean_tokens × d_model × 4 B`.

- Within-incentive labels, Qwen-7B (28 layers, d=3584), 305 responses,
  ~100 response tokens: **≈ 12 GB** — at or over a standard Colab instance.
  Llama (32 × 4096) ≈ 16 GB; Gemma (42 × 3584) ≈ 18 GB.
- Instructed-Pairs is worse: the ratified construction emits **two rows per
  TRUE statement over the whole `facts_true_false.csv`**. At ~1,000 true
  statements and ~15 statement tokens that is already ≈ 12 GB on Qwen, and
  the RepE file is larger than that.

`sklearn`'s `StandardScaler`/`LogisticRegression` then upcast the training
concatenation to float64, adding again on top per layer. `--limit` exists on
the builder but shrinking the ratified dataset to fit is a methodological
change, not an operational one. Nothing in the docstrings costs the
*accumulated* total — the memory note there only covers one text's capture.

## Methodology and contract findings

### F5 — the matched-arms audit cannot see which checkpoint an arm was initialized from
**HIGH · confidence high**

`planning/stage2-3.md` WP-2B asked for `init_adapter_path` **and its sha** to
be *guarded manifest identity*. What landed instead is a script-level
`init_provenance.json` written by `scripts/run_finetune.py`. Consequences:

- `train._train_manifest` records nothing about the init; `init_*` is absent
  from `GUARDED_MANIFEST_FIELDS` and from `matched_training_identity`.
- `recovery_report.audit_matched_arms` reads only `train_manifest.json`, so
  it **passes** on four arms initialized from different `M_D` checkpoints —
  or on an arm where `--init-adapter` was simply forgotten and which
  therefore trained a fresh LoRA from the base model. R_t between those arms
  is meaningless and the audit that exists to prevent exactly that (F73)
  says PASS.
- No digest of the init adapter is recorded anywhere in training, so an
  `M_D` checkpoint retrained in place is undetectable. (Eval rows do carry
  `adapter_digest`; `recovery_report` never compares it either.)

`init_provenance.json` does guard resume within one out-dir. It does not
guard *across* arms, which is what R_t depends on.

### F6 — activation-patching deception rates are scored with the LLM fallback off
**HIGH · confidence high**

`patching.run_activation_patching` calls
`score_response(scenario, INCENTIVE, text, hit_max_tokens=hit_max)` for both
the unpatched baseline and every patched layer — defaults, so
`use_llm_fallback=False`. There is no parameter to enable it and
`scripts/run_patching.py` has no `--llm-fallback` flag.

RESEARCH_SPEC (2026-08-13, re-pinned 2026-08-16): "Publishable runs enable
the fallback uniformly (`--llm-fallback`) … Extractors are never mixed across
runs." Every other reported deception rate in the project is produced with
gpt-5-mini extraction enabled. The patched and unpatched rates are the only
ones produced regex-only, so the same response text scores differently in the
two pipelines, and the reported `patched − unpatched` difference is computed
under a validity filter no other number uses. The rows also record no
extractor provenance at all, so this is invisible in the artifact.

### F7 — R_t has no pairing, coverage, or split diagnostic
**MEDIUM · confidence high**

`figures.bypass_effect_checked` exists precisely because
`metrics.bootstrap_ci` silently restricts to shared scenarios and would
otherwise return a real-looking `A_l` over an accidental overlap.
`metrics.recovery` has the identical hazard and **no** equivalent wrapper:
`recovery_report.evaluate_recovery` passes four row lists straight through.
Nothing checks that the four arms cover the same scenarios, that they used
the full 295-scenario `final` pool (ratified item 10), or that
`split == "final"` at all. A typo'd `--n` on one arm produces an R_t computed
on the intersection with no flag raised.

### F8 — reported `tau` and the statistic beside it can describe different populations
**MEDIUM · confidence high**

`metrics.bypass_effect` computes the `A_l` point estimate on the *shared*
scenarios (via `bootstrap_ci`'s restriction) but reports
`tau_base = incentive_gap(rows_base)["tau"]` over **all** base rows. Under
ratified P-S3 the sweep's base is the full 305-row `M_D` run while layers are
n=100, so `sweep_report`'s headline line

```
l*: layer L  A_l* = …  tau(M_D) = …  A_l*/tau(M_D) = …
```

divides a 100-scenario numerator by a 305-scenario denominator. Item 17
requires reporting that share, so it will be in the paper. The same pattern
applies to `recovery_report`'s table: `tau_LD…tau_IC` come from unrestricted
rows while `R_t` is computed on the intersection.

### F9 — the δ-curve's numbers are computed inside the renderer
**MEDIUM · confidence high**

`plotting.py`'s docstring: "It adds no statistics: every number on a figure
was computed by metrics.py / figures.py / sweep.py." But
`plotting.render_delta` computes `δ_l = a_rec − a_les` itself. The δ-curve is
a Stage-3 headline figure (spec §Stage 3: uniform ⇒ dispersed, non-uniform ⇒
concentrated), and its values therefore exist **only inside a PNG** — no
results record, no CI. The docstring is candid that a paired bootstrap
"is the metrics layer's job", but the metrics layer never got that function.

### F10 — the Stage-3 relocation verdict is not implemented, and its threshold is undefined
**HIGH · confidence high**

Spec §Stage 3 requires three things beyond R_t: identify layer `k`, the most
causally related layer in `M_t^{L,D}`; decide dispersed vs concentrated from
the δ-curve's uniformity; and classify each candidate layer as
*reconstructed* (causal relation in `~M_D` near-zero) or *strengthened*
(otherwise). `grep -rn 'reconstruct|strengthen|uniform'` over `src/` and
`scripts/` returns **nothing** (excluding `rng.uniform`).

Two distinct problems: the analysis is missing entirely, and "near-zero" and
"uniform" are **undefined thresholds**. Under AGENTS.md's one rule those are
pending decisions, not defaults to fill in. This is the paper's contribution
sentence — "if they do, we find where the capabilities relocated" — so it
should not be discovered at write-up time on Aug 18.

### F11 — two ratified sweep provisions have no implementation
**MEDIUM · confidence high**

- **P-S2** (per-layer MMLU/GSM8K on `l*`-candidates only): no driver runs

### F13 — ratified item 7's refusal audit has no tooling
**LOW-MEDIUM · confidence high**

Item 7 requires a human to review **every** refusal-flagged row in the first

### F14 — one metric name, two implementations, two provenance schemas
**MEDIUM · confidence high**

`wikitext2_ppl` is produced by `eval.compute_perplexity` **and** by
`eval.neutral_distribution_pass` (via `sweepdriver`). The arithmetic agrees —
both share `_sliding_windows`, the same masked `cross_entropy` sum and the
same NLL cap — so the numbers are consistent. The **configs** are not (F2),
and the sweep's ppl rows omit `dataset_id`, `dataset_revision`,
`attn_implementation`, `model_revision` and `adapter_digest`, all of which
Gate-1's ppl rows carry and `_gate1_competence_errors` insists on being
non-null. The same named metric therefore has two provenance grades.

### F15 — interp.jsonl rows carry no model or dataset provenance
**LOW-MEDIUM · confidence high**

`competence.jsonl` rows stamp `model_revision` and `adapter_digest` into
`config` (and Gate-1 refuses nulls). `interp.jsonl` rows do not:
`probe_auroc` records the recipe, `attention_jsd` records
`attn_implementation`, `activation_patching` records the protocol — none
records which model revision or adapter produced them beyond the
`adapter_path` string in `run_meta`. Corroboration is paper-facing.

### F16 — duplicated predicates and a second generation loop
**LOW · confidence high**

`patching.summarize_patched_scores` re-implements
`metrics.task_competence`'s predicate inline (ratified as a transplant,
because `task_competence` is defined on control rows), and
`patching._generate_pairs` re-implements `eval.generate_batch`'s padding,
encoding and cut-off detection. Both are documented as deliberate mirrors and
both share the low-level helpers (`_encode_chats`, `_eos_ids`), so nothing is
wrong today — but the answer to "is every reported quantity produced by
exactly one code path?" is *no* for task competence and for generation, and
the copies will not follow if the originals change.

### F17 — `patch_layer` / `patch_source` are now permanently dead row fields
**LOW · confidence high**

INTERFACES reserves them and `metrics.RUN_KEY_FIELDS` includes them so that
"bypass and patch are different causal evidence and never share a field."
Activation patching landed writing `interp.jsonl`, not results rows, so
nothing ever populates either field. Either the contract should say so or the
fields should go.

### F18 — the `damage_matched` arm has no producer and no spec basis
**LOW · confidence high**

It is in `INTERFACES.md`, `eval.VALID_ARMS` and a `figures.py` comment, and
appears nowhere in RESEARCH_SPEC.md. Nothing writes it.

### F19 — three JSD implementations, one pair unverified against the other
**LOW · confidence medium**

`eval.jsd_nats` (stdlib reference), `eval._jsd_mean_from_logits` (torch,
clamped mixture — tested against the reference in `test_neutral.py` ✓) and
`interp.jsd` (torch, additive `eps=1e-12` **inside both logs**, used for
attention JSD). The third is never cross-checked against the reference and
its smoothing biases the value differently. Both report "JSD in nats" and
both appear in the paper.

### F20 — the neutral pass recomputes the intact model 28–42 times
**LOW · confidence high**

`neutral_distribution_pass` runs *both* an intact and a bypassed forward per
window, and `run_layer_sweep` calls it once per layer. The intact side is
byte-identical across layers, so roughly half of ~2,200 1024-token forwards
per sweep are redundant. Lockstep is what keeps full-vocab distributions
from being held, but the intact pass could be cached per window across the
layer loop. Minutes, not hours — noted only because GPU budget is the binding
constraint this week.

### F21 — `tests/test_figures.py` runs zero tests and exits 0
**HIGH · confidence high · verified**

It is the only test file with no `__main__` runner and no `sys.path` insert.
Under the repo's documented invocation in the ML venv:

**MEDIUM · confidence high · verified**

### F23 — no test wires a driver's output into the report that consumes it, and the fixtures contradict each other
**HIGH · confidence high**

This is why F1 and F2 survived per-module review.

`tests/test_bypass.py:816-822` asserts the truth: intact rows carry

Structurally: `test_sweepdriver.py` verifies the driver writes correct rows;
`test_sweep_pure.py` verifies the report reads synthetic rows. Nothing joins
them. The same seam is untested for `sweepdriver → sweep_report` competence
records (F2) and for `run_finetune → recovery_report` manifests (F5).

### A1 — F1: the base/bypass grouping split

Rows built exactly as `eval._derive_gen_config` writes them: the intact base

```
layer_curve points: 1

entry layer 7 status UNMEASURABLE: no_baseline_run A_l None
```
