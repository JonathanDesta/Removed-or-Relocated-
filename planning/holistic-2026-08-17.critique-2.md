## New findings

### N1 — a layer with zero rows does not block l\*, while a candidate awaiting benchmarks does
**MEDIUM-HIGH · confidence high · reproduced**

The new gate collects `incomplete = [e for e in entries if
e["status"].startswith("PENDING")]` and withholds l* if it is non-empty. A
layer whose rows file exists but is empty gets status `NO ROWS`, which does
not start with "PENDING", so it does not block:

```
   layer 5 -> VIABLE
   layer 9 -> NO ROWS
   incomplete: []  l_star: 5
   VERDICT: layer 5 selected as l*
```

`NO ROWS` is the signature of a Colab session that died before writing a
single row for that layer — the strongest available evidence that the sweep
is unfinished. Because l* is `argmax A_l`, the unmeasured layer could have
been the true argmax, and the report says `layer 5 selected as l*` with no
qualification in the verdict line.

The hole existed before this round, but the new gate makes it *inconsistent*:
a candidate missing one benchmark now blocks the whole sweep, while a layer
missing all of its data does not. Whatever rule is chosen, those two cases
should not be ordered this way.

(`UNMEASURABLE` is a different case and correctly does not block: an A_l that
cannot be computed is a finding about that layer, not an unfinished job.)

### N2 — the merge feature added for the base competence records crashes on the merge it was added for
**MEDIUM · confidence high · reproduced**

`load_competence_records` now accepts several sources per key and refuses a
duplicated metric whose payload differs. The reason to pass two sources under
`base` is that item 2 needs MMLU/GSM8K from Gate-1's `competence.jsonl` while
item 3's PPL reference is the sweep's `base-competence.jsonl`. Both files
contain a `wikitext2_ppl` row for the same model, measured in different
sessions. The configs now match exactly; the *values* will differ in the last
bits:

```
ValueError: conflicting duplicate competence metric 'wikitext2_ppl' for 'base'
```

(reproduced with 8.1 vs 8.100000000000001 — two separate GPU sessions will not
agree bit-for-bit).

There *is* a working path: pass only Gate-1's `competence.jsonl`, whose PPL
config now matches the layer rows', and let the sweep's own
`base-competence.jsonl` go unused for scoring. Nothing in the code, the
docstring, or the disposition says that, and the newly added multi-source
support points the operator at the combination that raises.

### N3 — "greatest change in causal relation" is implemented as signed argmax
**MEDIUM · confidence high · reproduced**

`relocation.evaluate_relocation` computes
`max(point["delta_l"] for ...)` and takes the layers attaining it. The spec's
phrase is "the layer(s) with the greatest change in causal relation to
deception" — a magnitude. When every δ_l is negative (a real outcome: no
recovery anywhere, or recovery at one layer with compensating decreases
elsewhere), signed argmax returns the layer that changed **least**:

```
deltas -0.05 (layer 5) and -0.80 (layer 7)
signed argmax    -> [5]   (delta -0.05)
magnitude argmax -> [7]   (|delta| 0.80)
```

The chosen layers feed `candidate_layers`, which is exactly the set the human
is then required to classify as reconstructed vs strengthened — so the wrong
set is the set that gets reviewed. This is an interpretation of a spec phrase
made in code without a recorded decision: the same class of gap-filling the
implementer correctly declined for "near-zero" and "uniform". Either reading
may be intended; neither should be silent.

### N4 — three plausible base competence files, silently different comparability, and a docstring that names none of them
**MEDIUM · confidence high · reproduced**

`scripts/sweep_report.py`'s example still reads
`--competence base=results/sweep-md-qwen7b-base/competence.jsonl` — a path
the driver has never written. What now exists is `base-competence.jsonl`
(sweep-side PPL), `<tag>-base/rows.jsonl` (lesioned-sweep negotiation rows,
not competence), and Gate-1's `competence.jsonl`. The three behave
differently and none of the differences is documented:

| operator choice | Stage-1 sweep | Stage-3 (~M_D) sweep |
|---|---|---|
| Gate-1 `competence.jsonl` | all three checks work | **raises** (`permanent_bypassed_layer` None vs l*) |
| sweep `base-competence.jsonl` | PPL works, MMLU/GSM8K read `n/e` | PPL works, MMLU/GSM8K have no reference at all |
| both | **raises** (N2) | **raises** |

The Stage-3 crash is reproduced:
`ValueError: wikitext2_ppl competence config mismatch between base and layer 5`.
Refusing an incomparable base is correct behaviour; the problem is that the
operator has no way to know which file to pass, and two of the three natural
choices abort the report rather than degrade it.

(For the record: Stage-3 does not need `sweep_report` — the δ-curve goes
through `relocation_report`, which does not run these checks. But nothing
tells an operator that either, and `sweep_report` accepts the input happily
enough to crash on it.)

### N5 — the relocation classification the human is asked to type is mechanically determined
**LOW · confidence high**

The spec's rule is a set comparison: "We check whether the layer(s) with
concentrated recovery is the layer(s) with the greatest causal relation to
deception in M_t^{L,D}. If they are the same, then deception was entirely
relocated. Otherwise, deception was only partially relocated." Both sets are
already computed (`k_layers`, `max_change_layers`), so `entirely` vs
`partially` needs no threshold and no judgement — only "concentrated" does.
Requiring `--relocation` as free human input for a derivable value invites a
typo that the report then stamps as the authoritative verdict. The origin
classification is a different matter and is correctly left to the human.

### N6 — the coverage column is unparseable: `n/a` collides with its own separator

five. This is a paper-facing table.
